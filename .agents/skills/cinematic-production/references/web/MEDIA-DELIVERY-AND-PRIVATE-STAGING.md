# Media delivery and private staging reference

Status: research guidance only. No encoding, upload, deployment, Vercel setting change or remote endpoint test was performed.

## Formats, seeking and cache

Choose actual encodes by measured device capability and seek results, not filename extension. Container, video codec, profile/level, pixel format, resolution, frame rate and keyframe/GOP structure all matter. H.264 in MP4 is a candidate compatibility baseline, not a universal guarantee; HEVC, AV1 and VP9 alternatives need target-device validation. Query `canPlayType`/`MediaCapabilities.decodingInfo` with the exact configuration, then run real reverse/random seek tests. Capability reporting concerns support and playback smoothness/power efficiency; it is not a random-seek latency promise. The current MDN source also warns that smooth/power-efficient reporting can precede accumulated device statistics. [W03, W07, W08]

Shorter GOPs can reduce dependency decoding after a random seek at a transfer-size cost. An all-intra variant may improve access at another size cost. Test selected short-GOP and sequence variants using existing authorized media in a later task; do not prescribe a universal GOP interval or promise that frequent keyframes solve every browser. Place MP4 indexing metadata where startup does not require downloading the entire file, and verify the actual encoded result. Do not fetch every video into a full Blob solely to avoid Range behavior; that changes startup, transfer and memory costs. Keep the decoder count and active assets bounded. WebCodecs is a possible later low-level route with explicit chunk/frame lifecycle and worker options, not a free cure for missing frames or network latency. Its wall-clock playback examples do not satisfy this project's scroll contract. [W03, W44]

For sequence delivery, use a frame manifest with dimensions, count, timestamps if relevant, hash and locale/depth-mask dependencies. Decode the current neighborhood and release old bitmaps; compressed transfer bytes do not represent decoded pixel memory. One 1920 × 1080 RGBA8 image is about 7.91 MiB before additional buffers; 180 decoded frames would be about 1.39 GiB. Prefer a bounded window and explicit miss policy over all-frame preload. [W32, W47]

Verify media Range delivery with actual GETs, not only a HEAD or `Accept-Ranges` assertion. A supported `Range: bytes=0-1023` request should yield 206 with matching `Content-Range`, the correct 1024-byte payload and stable entity identity. Check a second offset and a valid out-of-bounds case producing the appropriate 416 response and length metadata; RFC 9110 also permits servers to ignore ranges and return 200, so 200 is not necessarily a protocol error but fails the intended partial-delivery gate. Verify through the final CDN/protection path. Test initial, warm-cache and seek-away/back requests. [W25, W48]

Use versioned content-hashed public asset names for long-lived immutable caching. Keep HTML/manifests revalidatable so they can select a new revision. Avoid immutable caching for replaceable files with unchanged URLs. Confirm MIME types, cache headers, validators, CORS for canvas-used remote media, actual bytes and behavior on expiry/failure. CORS failure may prevent canvas readback or compositing; same-origin approved assets simplify this. Do not label access-controlled/private content public-cacheable by default. `private` concerns shared-cache behavior; `no-store` is the directive when storage is forbidden. Cache policy does not itself authenticate access. [W25, W28, W29, W37]

## Private staging exclusion

Project adoption: reuse the existing Vercel project and the verified protected staging target. Do not create a new project/site. Specify the intended target explicitly with the current tool schema; omitting a target must never be assumed to mean private preview. Keep the public domain unchanged during review. General vendor configuration examples below do not expand that authorization.

Private research remains outside the repository, `public/`, build output, deployment input and Git history. A file under a publicly served static directory can be retrieved directly without a navigation link. Vercel's Build Output API explicitly exposes `.vercel/output/static` files at deployment paths. The present repository build copies `public/` recursively, so private files must never be placed there as a temporary convenience. [W38; read-only repository observation]

Use an explicit deployment-input allowlist and review the actual output manifest before any future authorized publish. `.gitignore` and `.vercelignore` address different boundaries. Vercel documents `.vercelignore` for files uploaded in deployment and supports allowlist-style rules. Do not infer that an ignore file also sanitizes separately generated build artifacts, prebuilt uploads, every Git integration path or an external asset bucket: inspect each actual path. Scan output for private research, unapproved media, source maps containing private source, environment files, credentials and private manuscript/case data. A noindex directive, robots.txt, obscure URL or unlinked route is not access control. [W27, W38]

If a later explicitly authorized review requires a Vercel staging project, configure and verify Deployment Protection before sharing its URL. The newly retrieved documentation distinguishes Standard Protection (except production domains) from All Deployments (all URLs). A separate private staging project may need All Deployments to protect a custom domain as well as generated URLs. Inspect the actual project and access recipients; do not silently protect or alter the public production site. No plan upgrade or paid method is authorized by reading these docs. [W26, W52]

Test unauthenticated retrieval of HTML and direct media paths on every relevant generated/custom alias. Test authenticated review, then an unauthenticated Range request to the same media: a byte-range path must not bypass protection. Also check external media hosts independently. Keep bypass credentials private. Deployment protection cannot retroactively remove a file previously published elsewhere.

Before a future push, inspect the connected Git/Vercel deployment wiring: Vercel supports automatic deployments on branch pushes. A statement that “Git push is separate from deploy” is not enough to establish that this particular project cannot deploy automatically. Current account/project wiring was not inspected. [W42]

Record source revision, output file list/hash, protection configuration evidence, authenticated/unauthenticated endpoint results, approved asset identities and rollback selection. A local build, instruction package or private preview does not certify publication or an operational service.
